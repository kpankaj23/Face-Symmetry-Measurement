# Face Symmetry Measurement

**A quality-aware, mirror-consistent facial asymmetry analysis system**
EE604 Image Processing course project, IIT Kanpur (2026).
Ankit Yadav (230150) · Ashish Porwal (230229) · Mahi Mittal (230617) · Pankaj Kumar (230733) · Prutha Vinay (230807)

Given one face photo, the system measures 2D left–right geometric asymmetry, globally and for
brows, eyes, nose, mouth and jaw. It **reports a number only when the photo supports one**:
every result comes with an accept / caution / reject decision and plain-language reasons.

> This is an image-based geometric indicator. It is not a medical assessment and not a
> measure of attractiveness.

## What is new (and what is not)

Landmark detection, mirrored-landmark comparison, regional heatmaps and Streamlit UIs already
exist in public tools ([FacialAsymmetry](https://github.com/nashokan/FacialAsymmetry),
[Varghaei et al. 2025](https://github.com/varghaei/face-aesthetics-analysis),
[irimid](https://github.com/irimidlab/irimid)). We do not claim those. Our contributions are:

1. **Correct correspondence + fitted symmetry axis.** Mesh vertices are paired with their exact
   anatomical twin, taken from MediaPipe's symmetric canonical model. The paired mesh is mapped
   to the 300-W 68-point layout with a mirror-consistent map fitted on the train split, and the
   symmetry axis is *estimated* rather than assumed vertical. The KD-tree matching used in prior
   tools picks the wrong partner for **58.3 %** of points.
2. **Mirror test.** The detector is run on the image *and* its mirror. Flipping cannot change a
   face's asymmetry, so the disagreement δ is a label-free landmark-reliability signal, and the
   average of the two detections cancels left/right detector bias.
3. **Quality/pose gate.** Seven signals (face size, sharpness, exposure, |yaw|, |pitch|, δ)
   plus per-region validity. Thresholds are a priori or set on the train split only.
4. **An evaluation protocol without symmetry labels.** We compare against the same measure
   computed on expert 68-point annotations, plus 26 controlled perturbations.

## Key results (LFPW test, 224 faces; 5,824 perturbed images)

| | Baseline M0 | Proposed M3 |
|---|---|---|
| Spearman ρ with annotation-based reference | 0.823 | **0.947** |
| Silent failures under perturbation (score reported, error > 1 % IOD) | n/a (no gate) | **3.6 %** (vs 8.1 % ungated M1) |
| Median score drift under perturbation (SD units) | 0.070 | **0.054** |

* The mirror test ranks images by true landmark error without labels (ρ = 0.59).
* **Head yaw dominates in-the-wild 2D asymmetry** (ρ = 0.91, even from expert annotations), so pose gating is essential.
* Negative result: an occluded eye is *not* detected by the mirror test, because the detector fills it in consistently.

All numbers are generated by the scripts below. See `paper/main.pdf` for the full write-up.

## Repository layout

```
app.py                      Streamlit demo (UI only; calls src/fsm)
src/fsm/                    measurement engine (no UI code)
  detector.py               MediaPipe Face Landmarker wrapper + pose from transform matrix
  mesh.py                   canonical mirror permutation, 68-pt layout, regions, 478->68 map
  geometry.py               fitted-axis asymmetry, KD-tree baseline, mirror test
  quality.py                image-quality signals and accept/caution/reject gate
  pipeline.py               end-to-end measurement and the four variants M0-M3
  viz.py                    overlays for app and figures
configs/                    canonical face model, fitted 478->68 map, gate thresholds (JSON)
experiments/                every experiment, table and figure (run in the order below)
results/tables, figures     CSV outputs and figures used in the paper
paper/                      LaTeX source (CVPR author-kit style) and compiled PDF
tests/                      unit tests for the geometry and gate (pytest)
models/face_landmarker.task Google MediaPipe Face Landmarker model (Apache-2.0)
```

## Setup and demo

```bash
python -m venv .venv && source .venv/bin/activate      # Python 3.11-3.13
pip install -r requirements.txt
streamlit run app.py
```

Upload a photo (or use the webcam option). Use the sidebar sliders (brightness, blur, rotation,
occlusion) to watch the gate react live. Results can be downloaded as CSV/JSON.

## Reproducing the experiments

Get LFPW first (see [`datasets/README.md`](datasets/README.md)), then:

```bash
pytest -q tests                                   # 15 unit tests
python experiments/cache_detections.py --split train
python experiments/cache_detections.py --split test
python experiments/fit_mp68_mapping.py            # train split only
python experiments/calibrate_gate.py              # train split only
cd experiments
python run_clean_eval.py                          # E1-E3, E8, risk-coverage
python run_perturbations.py                       # E4-E7 (~25 min on 2 CPU cores)
python summarize_perturbations.py                 # E9 ablation
python make_figures.py && python make_tables.py   # paper figures + LaTeX tables
cd ../paper && latexmk -pdf main.tex
```

## Privacy

The app processes uploads in memory and stores nothing. Paper and slide figures draw landmark
geometry only and never reproduce dataset photographs. Use only your own photos, or photos
used with the person's consent, for demos.

## Limitations

2D projection only (yaw and pitch change the measured value); reference landmarks contain
annotator noise; LFPW is small and in-the-wild; thresholds are calibrated on one dataset;
expression is not controlled. See Sec. 5 of the paper.
